## Failures and corrections

- The initial full run rejected the old explicit OpenAPI path allowlist after
  four intentional job routes were added. Updated the contract test, then the
  full suite passed; no authorization bypass or loosened schema assertion.
- Three initial frontend assertions expected a custom error sentence rather than
  the existing HTTP-status-specific safe-step copy. Corrected expectations while
  retaining stable-code and no-retry checks; all 90 passed.
- The added migration smoke initially left a SQLite connection open, so Windows
  refused temporary database cleanup (WinError 32). Used explicit connection
  closing; the entire smoke, including cleanup before emitting PASS, then passed.
- Full-page screenshot capture timed out. Retained and visually checked actual
  viewport captures instead; did not describe that as full-page success.

## Remaining gates

Browser submission/execution and durable warning review; automatic workers and
cooperative stopping; coordinated job retention/backup; native high contrast,
spoken screen-reader output and actual Remote Desktop testing remain undelivered.
Existing installations must explicitly configure/migrate their job store and
restart under owner control to enable this view. A source update does not hot-load
new backend routes into an already running service.
